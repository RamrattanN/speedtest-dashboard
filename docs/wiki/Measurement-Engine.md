# Measurement Engine

## Production policy

The current `main` branch and version 1.1.0 QA builds use the official Ookla
Speedtest CLI for production measurements.  They do not silently replace it
with the Python
`speedtest-cli` implementation.  The two engines use different test methods
and can report materially different throughput, latency, and server choices.

When the official CLI is missing, the dashboard remains available but new
production measurements pause.  The native controller and **Measurement
engine** panel explain that setup is required.

## Install the official CLI

Obtain the appropriate Windows x64, macOS Intel, or macOS Apple silicon
package directly from [Ookla](https://www.speedtest.net/apps/cli).  Ookla's
license and privacy terms apply.  Speedtest Monitor does not redistribute the
executable.

After installation, open **Connection Overview > Measurement engine**.  The
monitor searches:

- The path saved in dashboard settings.
- The `SPEEDTEST_OOKLA_CLI` environment variable.
- The application's `PATH`.
- Common Windows and macOS installation locations.

The discovered command is verified with `--version`.  It must identify itself
as Speedtest by Ookla.  This prevents the unrelated Python command with the
same `speedtest` filename from being accepted as the production engine.

On Windows, `C:\Tools\OoklaSpeedtest\speedtest.exe` is an automatically
detected location.  On macOS, `/usr/local/bin/speedtest`,
`/opt/homebrew/bin/speedtest`, `~/.local/bin/speedtest`, and
`~/bin/speedtest` are automatically checked.  Any other full path can be
saved in the dashboard.

## Compatibility mode

Compatibility mode is an explicit temporary choice.  It allows the bundled
Python engine when the official CLI is unavailable or fails.  Every CSV row
continues to identify its engine, and the dashboard shows that engine beside
Latest Result.

The dashboard selects the latest measurement engine by default for charts and
selected-window statistics.  Use the **Measurement engines** filter only when
you intentionally want to inspect another engine or compare historical data.

Do not compare Python and official Ookla results as if they were generated by
one measurement method.  Return to **Official Ookla CLI only** after setup is
complete to preserve a consistent baseline.

## Server selection

Engine choice and server choice solve different problems.  After confirming
the official engine, use **Test server selection** if automatic geolocation
chooses an unsuitable region.  Keep Automatic as the universal default, or
save a city and state, province, or country for regional calibration and
failover.
